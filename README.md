## [Clase 13: WordPress Práctico](https://dw3.netlify.app/#/11)

Taller de 3 horas. Herramientas: Local, navegador, VS Code y un asistente de IA (Claude, ChatGPT o similar). Toda la clase se trabaja sobre el sitio del área protegida que traen de tarea.

### Previa (tarea post entrega)

Investigar WordPress y hacer un pequeño ejercicio en [Local](https://localwp.com/):

1. Instalar Local by Flywheel.
2. Elegir un área protegida de Uruguay para (re)hacer su sitio.
3. Instalar Astra (theme).
4. Elegir un starter template para hacer la web de la reserva elegida.
5. Intentar tener lista al menos la home.

### Bloques

- **Bloque 1 (30'):** CMS vs. sitio estático, revisión de la tarea (plan B para quien no llegó: sitio nuevo en Local + Astra + starter template), ajustes iniciales (enlaces permanentes, zona horaria e idioma, comentarios, pingbacks y trackbacks desactivados, fuera el contenido demo).
- **Bloque 2 (60'):** Páginas vs. entradas, categorías y etiquetas, el Loop. Ejercicio en el sitio de la reserva: 1 página, 2 categorías, 2 entradas y una página de entradas (la home del template es portada estática).
- **Bloque 3 (75'):** Anatomía de un tema clásico (Astra), ajustar la home de la reserva con Gutenberg (hero + grilla de 3 atractivos), IA para copy (verificando los datos) y CSS.
- **Bloque 4 (15'):** Revisión en vivo, errores comunes y checklist de cierre.

### Tarea 1: de HTML a tema de WordPress

Convertir el sitio estático de los módulos anteriores en un tema básico de WordPress en Local.

1. Crear la carpeta del tema en `wp-content/themes/` (sin espacios ni mayúsculas, ej. `mi-sitio-theme`).
2. Mover el CSS a esa carpeta como `style.css` y agregarle la cabecera:
    ```css
    /*
    Theme Name: Mi Primer Tema
    Author: [Nombre]
    Version: 1.0
    */
    ```
3. Partir el HTML en `header.php` (con `<?php wp_head(); ?>` antes de `</head>`), `index.php` (con `get_header()` y `get_footer()`) y `footer.php` (con `<?php wp_footer(); ?>` antes de `</body>`).
4. Usar `get_template_directory_uri()` para las rutas a imágenes y `get_stylesheet_uri()` para el CSS.
5. Activar el tema en _Apariencia > Temas_ y verificar que se vea igual que el sitio original.

**Se evalúa:** que el tema se active sin error fatal de PHP, que el HTML esté bien repartido en los 3 archivos, que estén `wp_head()` y `wp_footer()`, y que no haya rutas rotas a CSS ni imágenes.

### Tarea 2: Reserva viva (tema hijo + patrón + avistamientos)

Sobre el sitio del área protegida en Local:

1. **Tema hijo de Astra.** Crear `reserva-child/` con `style.css` (cabecera con `Template: astra`) y `functions.php` que cargue sus estilos con `wp_enqueue_style`. Activarlo. Astra no se toca.
2. **Patrón de bloques "Ficha de especie".** Armar la ficha en Gutenberg (foto, nombre común, nombre científico, estado de conservación, dónde verla), copiar el marcado desde el _Editor de código_ y registrarlo como patrón en `reserva-child/patterns/ficha-especie.php`. Tiene que aparecer en el insertador, pestaña _Patrones_.
3. **Contenido real.** Publicar 4 entradas en la categoría _Flora y fauna_ usando el patrón, con especies que existan en esa reserva. Fotos con licencia libre (ej. [Wikimedia Commons](https://commons.wikimedia.org/)) y crédito. Datos verificados contra el sitio oficial o el [SNAP](https://www.ambiente.gub.uy/oan/sistema-nacional-de-areas-protegidas/).
4. **"Últimos avistamientos" en la home.** Con JS vanilla, traer las 3 últimas entradas de esa categoría desde la REST API (`/wp-json/wp/v2/posts?categories=ID&per_page=3&_embed`) y mostrarlas como tarjetas. El script se carga con `wp_enqueue_script` solo en la portada (`is_front_page()`), nunca pegado en un bloque HTML.
5. **`IA.md`.** Los prompts usados para los puntos 1, 2 y 4, qué devolvió la IA que estaba mal o no funcionaba, y cómo lo corrigieron.

**Entrega:** repo de GitHub con la carpeta `reserva-child/` (con `IA.md` adentro) y 3 capturas: home con avistamientos, una entrada con la ficha y el patrón en el insertador.

**Defensa (5' en clase):** se abre el `functions.php` y se pide explicar una línea al azar. Si no la pueden explicar, ese punto no cuenta.

| Se evalúa | Peso |
|---|---|
| Tema hijo correcto (activa sin error, Astra intacto, CSS encolado) | 20% |
| Patrón registrado desde el tema y usado en las 4 entradas | 25% |
| Avistamientos vía REST + `wp_enqueue_script` condicional | 25% |
| Contenido real, verificado, con créditos; categorías bien usadas | 15% |
| `IA.md` honesto + defensa | 15% |

## [Clase 14: Documentación para agentes + En vivo](https://dw3.netlify.app/#/12)

Taller de 3 horas (en las slides, _clase 11_). Se trabaja en el repo de `reserva-child` (Tarea 2) con el agente que usen (Claude Code, Codex, Cursor…).

- **Bloque 1 (20'):** por qué documentar para agentes: el agente arranca de cero en cada sesión y leer cuesta tokens.
- **Bloque 2 (50'):** el sistema: `AGENTS.md` como índice (y `CLAUDE.md` con `@AGENTS.md`), reglas para no quemar tokens, reglas de _modo pareja_ (el agente propone, el alumno ejecuta y explica), y `docs/site.md` con lo básico del sitio.
- **Bloque 3 (60'):** workstreams (`docs/ws/contenido.md`, `tema.md`, `deploy.md`) con comandos de wp-cli probados para correr en el _Site Shell_ de Local; toda tarea cierra actualizando `site.md` y `log.md`. Ejercicio: armar el sistema y pedirle al agente "quiero sumar 2 especies a Flora y fauna".
- **Bloque 4 (50'):** en vivo gratis en un sandbox de [Pantheon](https://pantheon.io/plans/pricing) (`dev-*.pantheonsite.io`): crear el sandbox, `wp search-replace … --export=reserva.sql` desde Local, subir código en modo SFTP, importar base y `uploads`, chequeo final y `ws/deploy.md`.

```
wp-content/themes/reserva-child/
├── AGENTS.md          ← índice
├── CLAUDE.md          ← @AGENTS.md
└── docs/
    ├── site.md
    ├── log.md
    └── ws/
        ├── contenido.md
        ├── tema.md
        └── deploy.md
```
